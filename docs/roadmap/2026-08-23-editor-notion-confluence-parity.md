> 상태: 구현 백로그 정본(에디터 영역 상세)
> 범위: `wiki-front` 에디터·보기 렌더, 저장 포맷 영향, 백엔드 계약 파급
> 상위 문서: [Notion·Confluence DC 갭 분석](2026-08-16-notion-confluence-gap-analysis.md) §4.2 —
> 이 문서가 §4.2의 에디터 행들을 상세 전개한다.
> 선행 실측: [편집기 요소 심화 (2026-08-03)](2026-08-03-editor-elements-depth.md) §0 — 이 문서의
> "현재" 열은 그 실측 + 이후 커밋(이미지 업로드 레일·공동 편집)을 반영해 갱신했다.

## 1. 문제 정의

### 문제

현재 에디터는 "마크다운으로 표현 가능한 블록"까지는 컨플루언스 클론으로 동작하지만,
Notion·Confluence 사용자가 **매일 쓰는 편집 동작의 절반 이상이 없다** — 블록 드래그 이동,
토글, 멘션, 인라인 서식(색·정렬), 표 셀 병합, 임베드, 수식·다이어그램. "에디터가 좋아서
Notion을 쓴다"는 사용자를 데려오려면 콘텐츠 모델(블록 종류)보다 **입력 UX(단축·조작감)**가
먼저 갖춰져야 한다.

### 왜 지금인가

- 공동 편집(W17)·서버 댓글(W16)이 붙어서, 이제 사용자 체감 병목이 "협업"에서 "편집기 표현력"으로 이동했다.
- W19 마이그레이션이 가져올 Notion/Confluence 원본에는 아래 갭 블록들이 실제로 들어 있다 —
  에디터가 표현 못 하면 `opaque` 비율이 올라가 이전 품질이 떨어진다. IR v1 노드 범위(`panel`,
  `columns`, `image`, `mention`, `pageLink` 등)와 에디터 지원 범위가 맞아야 한다.

### 성공지표 (검증 가능한 완료 기준)

- Must 완료 시: 대표 Notion 페이지(토글·콜아웃·멘션·표 포함)와 Confluence 페이지(expand·
  status·layout 포함)를 붙여넣기/이전했을 때 **opaque 없이** 렌더된다.
- 블록 이동·복제·삭제가 마우스(드래그 핸들)와 키보드 양쪽으로 되고 왕복 저장이 안전하다.
- 기존 639+개 테스트 회귀 없음 + 신규 블록마다 마크다운 왕복 테스트.

## 2. 비교 기준 요약

**Notion 에디터에서 가져올 것** — 블록 중심 조작(드래그 핸들·`/` 메뉴·블록 전환 turn-into),
토글, 콜아웃, 멘션(@사람/@페이지/@날짜), 동기화 블록, 인라인 수식·색상, DB 인라인(별도 트랙).
**Confluence 에디터에서 가져올 것** — 패널·expand·status·date 같은 "문서 장식" 매크로, 표
심화(셀 병합·배경·헤더 행/열), layout(열), TOC·anchor, 첨부 매크로, Jira 임베드.

공식 근거: [Notion — Writing & editing basics](https://www.notion.com/help/writing-and-editing-basics),
[Notion — Columns, headings, & dividers](https://www.notion.com/help/columns-headings-and-dividers),
[Confluence — Insert elements/macros](https://support.atlassian.com/confluence-cloud/docs/what-are-macros/),
[Confluence — Tables](https://support.atlassian.com/confluence-cloud/docs/insert-a-table/).

## 4. 우선순위 (MoSCoW 종합)

**Must** — "Notion·Confluence에서 왔을 때 즉시 아쉬운 것" + 마이그레이션 손실 최소화:
1. ~~토글(expand) 블록~~ — **완료(2026-08-23)**: `:::details[제목]` A안 확정, 중첩 마커 자동 계산
2. ~~문서 전역 블록 드래그 핸들(이동)~~ — **실측 정정**: `GlobalDragHandle`로 이미 존재
   (WikiEditor:139). 초판의 "열 내부만" 판정은 오독. 복제·삭제 컨텍스트 메뉴만 Should로 이동
3. 표 심화 1차: 셀 병합·헤더 행/열 지정·열 너비 저장 — **유일한 잔여 Must(구조)**, ADR 선행
4. ~~이미지 리사이즈·캡션~~ — **완료(2026-08-23)**: 폭은 src `#w=` 프래그먼트(표준 왕복 유지),
   캡션은 표준 title. 드래그 + 키보드(화살표/Delete) 대체 경로 포함
5. ~~콜아웃 보기 렌더 아이콘~~ — **실측 정정**: `ALERT_ICONS`로 이미 구현돼 있었다(8/3 실측 이후 반영분)
6. ~~체크리스트 중첩~~ — **완료(2026-08-23)**: `nested: true`, 표준 들여쓰기 왕복
7. ~~사용자 멘션(@)~~ — **완료(2026-08-23)**: 저장은 표준 링크 `[@이름](user:id)`(열린 결정 해소 —
   타 렌더러에서 "@이름" 링크로 우아한 열화). `@` 자동완성은 org 디렉터리, 보기 렌더는 칩.
   멘션 알림 이벤트는 W18에서 잇는다

**Should**: 글자색·하이라이트, status 칩, 수식, 언어 검색+줄번호 코드 블록, 슬래시 검색,
turn-into, HTML 붙여넣기 변환, 동영상 첨부, 파일 칩, anchor 복사, 밑줄(정책 결정 후), 열 1·4·5 노출.
**Could**: 임베드 allowlist, mermaid, 날짜 멘션, 북마크 카드, 다중 선택, 찾기/바꾸기, 텍스트 정렬.
**Won't(now)**: 동기화 블록(stable block ID 후), DB/페이지 속성(확장 트랙), 각주.

## 5. 저장 포맷 영향 — ⚠️ 저장 포맷 재논의 게이트

Must 7개 중 **4개(토글·표 병합·이미지 속성·멘션)가 순수 GFM으로 표현 불가**다. 선택지:

- A. 확장 문법 계속 증설(`:::details`, 이미지 `{width=}` 속성, `@[user:1]`) — 정본은 계속
  마크다운 문자열. 지금까지의 노선(`:::` 패널, `::::columns`)과 일관.
- B. 표 병합 같은 구조적 요소만 제한적 HTML 서브셋 허용 — 보기 렌더 raw HTML 금지 정책과
  충돌하므로 sanitize allowlist ADR 필요.
- C. 정본을 구조화 포맷(ProseMirror JSON/IR)으로 전환 — 기존 확정 결정
  ("revision은 Markdown") 번복이라 **사용자 승인 없이 진행 금지**.

권고: **Must 범위는 A로 소화 가능**(토글·멘션·이미지 속성·콜아웃 커스텀). 표 병합만 A로는
추하므로(B 또는 표 한정 속성 문법) 구현 착수 전 ADR 1건을 쓴다. C는 지금 열지 않는다.

## 6. 영향 리포 / 크로스커팅

- `wiki-front` — 에디터 확장·remark 플러그인·보기 렌더(양쪽 왕복 계약 §3 유지), 신규 블록마다
  `editor/extensions/base.ts` 단일 등록 원칙.
- `wiki-backend` — 멘션: 알림 이벤트(W18)와 사용자 디렉터리 조회. 동영상: inline MIME allowlist
  확장(현재 raster 4종). 임베드: CSP/sanitize 정책.
- `platform-backend(org-service)` — 멘션 대상 검색용 사용자 디렉터리 API(상위 문서 §계정·권한).
- W19 마이그레이션 — Notion `toggle`/`callout`(이모지·색), Confluence `expand`/표 병합이
