> 기준: Confluence(Cloud/Data Center 공통 기능 표면)
> 대조 대상: `wiki-front`(commit `cca5b19`), `wiki-backend`(대조 시점 Flyway V1~V12 → 구현 후 V15), `collaboration-service`
> 선행 문서: [Notion·Confluence DC 갭 분석(2026-08-16)](2026-08-16-notion-confluence-gap-analysis.md),
> [에디터 동등성(2026-08-23)](2026-08-23-editor-notion-confluence-parity.md)
>
> 앞 두 문서는 **Notion을 함께 놓고 본 아키텍처 백로그**다. 이 문서는 거기서 한 번 더 좁혀서
> **"컨플루언스를 쓰던 사람이 우리 위키에 와서 없다고 느낄 기능"**만 제품 기능 단위로 재정리했다.

## 1. 결론

에디터·실시간 공동 편집·페이지 제한은 컨플루언스 수준에 도달했다. 남은 격차는 **문서를 쓰는 기능이 아니라
문서를 관리하는 기능**에 몰려 있다. 지우면 복구할 수 없고, 분류할 수단이 없고, 이미지 외의 파일을 붙일
화면이 없고, 밖으로 꺼낼 방법이 없다.

우선순위 상위 4개 묶음을 이번 스프린트(W21) 범위로 확정했다.

| 묶음 | 왜 먼저인가 |
|---|---|
| 휴지통·복원·보존 | 유일하게 **되돌릴 수 없는** 결함이다. 나머지는 없어도 데이터가 사라지지 않는다 |
| 라벨 + 백링크 | 문서가 수백 건이 되는 순간 트리만으로는 못 찾는다. 검색 필터 확장의 선행 조건 |
| 첨부파일 관리 + 내보내기 | 지금은 이미지 말고는 파일을 올릴 화면이 없고, 내용을 꺼낼 경로가 전혀 없다 |
| 인라인 댓글 + watch | 컨플루언스 협업의 기본 단위. 페이지 댓글만으로는 "이 문장"을 가리킬 수 없다 |

## 4. W21 스프린트 범위 — 인수조건

### W21-1 휴지통·복원·보존

- 페이지 삭제는 소프트 삭제다. 본문·리비전·댓글·첨부 객체가 남는다.
- `children=cascade` 삭제는 하위를 함께 휴지통으로 보내고, 복원은 그 묶음을 함께 되살린다.
  독립적으로 먼저 버려진 하위 묶음은 함께 복원되지 않는다.
- 휴지통 목록은 스페이스 단위로 보이고, 사용자가 직접 버린 항목만 행으로 뜬다(하위는 개수로 표시).
- 부모가 사라진 뒤 복원하면 루트로 올라오고, 그 사실을 사용자에게 알린다.
- 영구 삭제와 휴지통 비우기는 스페이스 ADMIN만 할 수 있다.
- 삭제된 페이지는 트리·검색·첨부·댓글·알림·링크 어디에서도 보이지 않는다.
- 보존 기간(`platform.wiki.trash.retention`)이 설정되면 그 기간이 지난 항목을 자동으로 영구 삭제한다.
  기본값은 자동 삭제 없음이다.

### W21-2 라벨 + 백링크

- 페이지에 라벨을 붙이고 뗄 수 있고, 편집 권한이 있는 사람만 바꿀 수 있다.
- 스페이스의 라벨 목록과 라벨별 페이지 목록을 볼 수 있다.
- 라벨은 검색 결과에서 필터로 쓸 수 있다. (→ §4-1: search-service 색인이 선행이라 이번 범위에서 제외)
- 본문의 `[[페이지]]` 내부 링크는 저장 시 역방향으로 기록되고, 페이지 하단에 "이 페이지를 링크한 문서"로 보인다.
- 페이지를 삭제·복원하면 백링크 목록이 그에 맞게 바뀐다.

### W21-3 첨부파일 관리 + 내보내기

- 페이지에 첨부파일 탭이 있고, 본문에 넣지 않은 파일도 올릴 수 있다.
- 목록에서 파일명·형식·크기·올린 사람·시각을 보고 내려받거나 지울 수 있다.
- 지울 때는 본문이 그 파일을 참조 중이면 경고한다.
- 페이지를 Markdown·HTML로 내보낼 수 있고, 하위 포함 여부를 고를 수 있다.
- 내보낸 HTML은 이미지가 포함되어 오프라인에서도 열린다.

### W21-4 인라인 댓글 + watch

- 본문 텍스트를 선택해 댓글을 달 수 있고, 그 구간이 하이라이트로 표시된다.
- 스레드를 해결하면 하이라이트가 사라지고, 다시 열 수 있다.
- 본문이 바뀌어 앵커 텍스트를 못 찾으면 스레드는 사라지지 않고 "위치 없음"으로 남는다.
- 페이지를 구독·해제할 수 있고, 구독자는 수정·댓글 알림을 받는다.
- 페이지를 만들거나 수정하면 자동으로 구독되며, 사용자가 해제할 수 있다.

## 4-1. 구현 결과 (2026-08-28)

네 묶음 모두 백엔드·프론트 양쪽을 구현하고 게이트를 통과했다.
검증: wiki-backend 204 테스트(실제 PostgreSQL Flyway V1→V15 검증 포함), wiki-front 809 테스트 +
`pnpm typecheck` + production build.

| 묶음 | 백엔드 | 프론트 |
|---|---|---|
| W21-1 휴지통 | V13 소프트 삭제(`@SQLRestriction`), `TrashService`(목록·복원·영구삭제·비우기), 보존 기간 스케줄러 | `/spaces/:id/trash` 화면, 사이드바 진입점 |
| W21-2 라벨·백링크 | V14 `page_label`·`page_link`, 저장 시 링크 재색인 | 페이지 하단 라벨 칩, 백링크 섹션, `/spaces/:id/labels` |
| W21-3 첨부·내보내기 | 변경 없음(업로드 API가 이미 CONFIRMED로 저장) | 첨부 목록·업로드·삭제 UI, Markdown/HTML 내보내기 |
| W21-4 인라인 댓글·구독 | V15 앵커·해결 상태·`page_watch`, 알림 대상을 구독 원장으로 이관 | 본문 하이라이트·스레드 패널, 구독 토글 |

### 설계에서 조정한 것

- **인라인 앵커는 렌더된 본문 기준이다.** 처음엔 서버가 마크다운 원문과 대조하려 했으나,
  서식을 가로지르는 선택(`배포는 **금요일**에`)은 원문에 그대로 없어 정당한 선택을 거부한다.
  서버는 앵커를 보관만 하고 위치 찾기는 렌더러가 한다.
- **PDF 내보내기는 브라우저 인쇄로 넘겼다.** 자체 렌더러 없이 만든 PDF는 표·코드 블록이 화면과
  어긋나 신뢰를 깎는다. Markdown(무손실)·HTML(이미지 내장)만 파일로 낸다.
- **알림 대상 모델을 교체했다.** "작성자 + 편집자" 계산식은 끌 수가 없어 `page_watch` 원장으로
  옮겼다. 기존 사용자는 V15 백필(프론트는 `normalize`)로 승계된다.
- **검색의 라벨 필터는 아직 없다.** 검색 색인은 별도 서비스(search-service)라 라벨을 색인해야
  한다. 위키 안의 라벨 탐색(`/labels`)까지가 이번 범위다.

## 5. 이번 범위 밖으로 남기는 것

| 항목 | 이유 |
|---|---|
| 블로그·개인 스페이스 | 콘텐츠 타입 추가는 트리·검색·권한을 모두 건드린다. 별도 웨이브 |
| 페이지 템플릿 | 라벨·내보내기보다 요구가 약하고, 블루프린트까지 가면 범위가 크다 |
| 감사 로그 | org-service 확장이 선행 |
| 첨부 버전·미리보기 | 첨부 화면이 먼저 있어야 필요가 드러난다 |
| 리액션·공유·작업 목록 | 협업 2차 |
| 애드온 플랫폼 | ADR 선행(갭 분석 §5.6) |

## 6. 규모 대응 (2026-08-29)

"문서량이 2TB면 버티는가"에서 시작한 작업. 용량 자체보다 **요청당 비용이 스페이스 크기에
비례하는 지점**이 먼저 무너진다고 판단해 그 세 곳을 순서대로 잡았다.

### 6.1 권한 판정 — 완료

제한 판정이 요청마다 스페이스의 전 페이지로 부모 맵을 만들고 있었다. 페이지 한 장을 여는
비용이 스페이스 크기에 비례했다는 뜻이다.

대상의 **조상 폐포만** 읽도록 바꿨다(재귀 CTE 1쿼리 + 그 id들의 제한 행). 스페이스 전량이
정말 필요한 곳은 트리 필터 하나뿐이라 거기만 남겼다. 캐시를 쓰지 않은 것은 의도다 —
제한·트리 변경 직후의 스테일 인덱스는 그대로 누출이라, 무효화가 완벽해야만 안전한 캐시보다
질의를 싸게 만드는 쪽을 택했다.

회귀 가드: `PermissionQueryScaleTest` — 5페이지 스페이스와 300페이지 스페이스의 조회 질의
수가 같아야 한다(Hibernate statistics).

### 6.2 리비전 보존 — 완료 (정책: 전부 보관 + 압축)

저장할 때마다 본문 전체가 새 리비전으로 복사된다. 이력을 지우지 않기로 했으므로 남은 수단은
크기를 줄이는 것뿐이다.

V16에서 gzip 압축본을 BYTEA에 담고 `STORAGE EXTERNAL`로 TOAST의 이중 압축을 막았다.
512자 미만은 gzip 헤더 때문에 오히려 커져 평문으로 둔다. 기존 행은 그대로 두고 엔티티가 둘 중
있는 쪽을 읽으므로 일괄 변환이 필요 없다.

### 6.3 트리·전체목록 지연 로딩 — 완료 (전면 리팩터)

**끝난 것 (백엔드):** 화면 단위 조회 API 5종 — 직계 자식(`childCount` 포함), 조상 체인,
후손 폐포, 제목 정확 조회, 제목 부분 검색. 전부 effective VIEW로 걸러 나가고, 누출 테스트가
다섯 경로를 모두 덮는다(`TreeApiTest`).

**끝난 것 (프론트 소비처 이관):**

| 소비처 | 이전 | 지금 |
|---|---|---|
| `[[제목]]` 링크 해석 | 스페이스 전 페이지에서 제목 색인 | 본문에 등장한 제목만 조회 |
| `[[` 자동완성 | 전 페이지 필터 | 서버 제목 검색(빈 질의는 최상위 문서) |
| 링크 칩 존재/부재 | 전 페이지 | 문서에 등장한 제목의 조회 결과 캐시 |
| 붙여넣기 링크 메뉴 | 전 페이지에서 id 조회 | URL에서 id만 뽑고 제목은 서버 조회 |
| 공동 편집 세션 | 전 페이지 배열 보유 | 편집 화면과 같은 링크 캐시 공유 |
| 하위 페이지 목록 | 전 페이지 필터 | 직계 자식 조회 |
| 내보내기(하위 포함) | 전 페이지에서 서브트리 계산 | 후손 폐포 조회 + 클라이언트 정렬 |

**끝난 것 (트리 뒤집기, 2026-08-29):**

- `useSpaceTree` — 최상위만 먼저 받고 펼칠 때 한 단계씩 받는다. 접었다 펴는 것은 재요청하지
  않고, 생성·이동·삭제 후에는 **펼쳐 둔 자리만** 다시 읽는다.
- `PageTree` 기본값이 "펼침"에서 **"접힘"**으로 바뀌었다. 화살표는 서버가 준 `childCount`로
  그린다 — 자식을 받아보기 전에 알아야 하기 때문이다.
- 깊은 링크(`/pages/손자`)로 들어오면 조상 체인을 받아 그 자리까지 펼친다. 트리를 다 받지
  않으므로 펼쳐 주지 않으면 현재 위치가 사이드바에 나타나지 않는다.
- 사이드바 제목 검색이 서버 검색이 됐고 결과는 **평면 목록**이다. 매치마다 조상 체인을 따로
  받아오면 한 번 타이핑에 요청이 수십 개가 된다.
- 별표 스냅샷 최신화는 별표된 id만 서버에 묻는다(`/pages/by-ids`). 로드된 노드만으로 맞추면
  접힌 가지의 별표 제목이 조용히 낡는다.
- `WikiOutletContext`에서 `pages`가 사라졌다 — "스페이스의 전 페이지"라는 것이 화면에 더는
  존재하지 않는다.

**의도한 동작 변경**

| 이전 | 지금 | 이유 |
|---|---|---|
| 사이드바가 전부 펼쳐진 상태로 시작 | 최상위만, 펼치면 로드 | 전량 로드가 곧 규모 상한이었다 |
| 검색이 매치 + 조상 체인을 트리로 유지 | 매치만 평면 목록 | 조상 체인을 매치마다 받으면 요청이 폭증한다 |

### 6.4 부채 정리 (2026-08-29)

| 항목 | 처리 |
|---|---|
| 스페이스 개요가 전량 조회 | **해결.** 개요는 최상위 목록 + 최근 업데이트(전용 조회)만 읽는다. 전체 계층을 한 화면에 펼치는 것은 그만뒀다 — 조망은 "무엇이 있는지"까지면 충분하고, 그 아래는 사이드바 트리와 각 문서가 맡는다 |
| 이동 다이얼로그가 대상 스페이스 전량 조회 | **해결.** 컨플루언스처럼 "쳐서 찾는" 위치 선택으로 바꿨다(검색어 없으면 최상위). 만들기 다이얼로그의 상위 위치 선택도 같다 |
| 레거시 전체 트리 API | **제거.** `GET /spaces/{id}/pages`와 `listPages`를 양쪽에서 지웠다. 인증된 사용자면 누구나 스페이스 전량을 끌어올 수 있는 무제한 질의가 API 표면에서 사라졌다 |
| 테스트 전용 리포지토리 메서드 | **제거.** 휴지통 포함 전량 삭제는 테스트 헬퍼(`TestPages`)로 옮겼다 — 운영 코드에 그런 수단이 존재하지 않아야 한다 |
| 초기 JS chunk | **완화.** 편집 화면을 지연 로딩해 1.56MB → 1.20MB(gzip 509KB → 377KB). 편집기 청크 359KB는 읽기만 하는 사용자가 받지 않는다 |
| 검색 결과의 계층 | **남김.** 평면 목록이라 "어느 폴더 아래인지"가 보이지 않는다. 경로 라벨을 붙이려면 매치마다 조상 조회가 필요해 비용 대비 이득을 더 봐야 한다 |

전량 조회가 남은 곳은 이제 없다. 테스트가 상태를 통째로 확인해야 할 때는 지연 트리 API를
재귀로 훑는 헬퍼(`allPagesForTest`)를 쓴다 — 운영 경로에는 같은 수단이 없다.

## 7. W22 — 버전 이력 완성 (2026-08-29)

이전 한계 둘을 닫았다. 비교가 직전 버전에 고정돼 있었고, 이력에 "무엇을 왜 고쳤는지"가 없어
버전이 쌓이면 어느 것이 되돌릴 지점인지 알 수 없었다.

- **변경 요약(V17)** — 저장할 때 한 줄을 남기면 그 버전의 이력에 붙는다. **선택 입력**이다:
  강제하면 "수정"만 적힌 이력이 쌓여 오히려 신호가 죽는다. 공백만 적은 요약은 없는 것으로 눕힌다.
- **복원 자동 기록** — 복원이 만드는 새 버전에는 "vN 버전으로 복원"이 남는다. 어느 버전에서
  되돌렸는지가 다음 사람에게 가장 중요한 정보다.
- **임의 두 버전 비교** — 히스토리에서 비교 기준을 고른다. 기본값은 종전대로 직전 버전.
- **버전 본문 단건 조회** — 목록은 메타만 준다. 여기서 실측 결함을 하나 잡았다: 백엔드 모드의
  버전 목록은 본문을 담지 않는데 미리보기·diff가 그 목록의 `body`를 그대로 읽고 있어 **빈 화면**이
  나왔다. 화면에 필요한 두 버전만 단건으로 읽어 캐시한다.

부수 수정: 편집 화면 지연 로딩 이후 편집 관련 테스트가 간헐적으로 5초 예산을 넘겼다(동적 import가
테스트당 예산 안에서 일어났다). 테스트 하네스가 모듈을 미리 데운다 — 앱 동작은 그대로다.

## 8. W22 — 스페이스 설정 (2026-08-29)

백엔드에 이름 변경·삭제 API가 있는데도 **화면 진입점이 없어** 한번 만든 스페이스는 이름도 못
고치고 지울 수도 없었다. 사이드바 하단에 설정을 두고 세 탭으로 묶었다.

- **일반** — 이름·설명 수정.
- **권한** — org-service grant를 직접 다룬다. 사용자/팀 × 보기·편집·관리.
- **삭제** — 되돌릴 수 없음을 글로도 알리고 확인 다이얼로그를 받는다.

### org-service 권한 범위를 넓혔다

grant API가 **전역 관리자만** 허용하고 있어, 스페이스 소유자가 자기 공간에 사람을 초대할 수
없었다. `requireResourceAdmin`을 추가해 **그 리소스의 ADMIN**도 관리할 수 있게 했다.
컨플루언스도 스페이스 관리자가 그 스페이스 권한을 관리한다.

경계는 그대로 지킨다 — 스페이스 ADMIN이라도 다른 스페이스나 GLOBAL 권한은 만지지 못하고,
EDITOR는 자기가 속한 스페이스라도 권한을 볼 수 없다. 회수는 대상 grant를 먼저 읽어
"그 리소스의 관리자인가"를 물은 뒤에 지운다.

권한 목록 조회가 403이면 화면은 그 사실을 그대로 보여준다. 빈 목록으로 덮으면 "권한이 없는
건지 아무도 없는 건지"를 구분할 수 없다.
