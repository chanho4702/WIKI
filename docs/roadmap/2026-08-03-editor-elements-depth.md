기획 전에 코드로 확인했다. **이미 있는 것을 다시 기획하지 않기 위해서다.**

## 1. 문제 정의

### 문제

1. **열 레이아웃이 2·3열에 갇혀 있다.** 레퍼런스는 1~5열을 준다. `Math.max(2, count)`가 1열을
   원천 차단하고, 4·5열은 노출 경로가 없다. 07-26 기획이 "3열 초과"를 제외로 잘랐던 근거는
   당시 레퍼런스에 없었기 때문 — 이번 캡처가 그 전제를 뒤집는다.
2. **코드 블록이 길어지면 읽히지 않는다.** 줄 번호가 없어 리뷰에서 "몇 번째 줄"을 가리킬 수 없고,
   긴 줄은 가로로 흘러 잘린다. 언어 목록은 15개 고정이라 그 밖의 언어는 강조를 포기해야 한다.
3. **빈 문서 앞에서 무엇을 해야 할지 모른다.** 레퍼런스는 본문 아래 퀵바로 첫 행동을 유도하는데,
   우리는 플레이스홀더 한 줄뿐이다.

### 왜 지금인가

편집기 코어가 완성돼 있어 이번 작업은 **새 저장 포맷을 거의 만들지 않고 기존 것을 넓히는 일**이다.
미루면 문서가 쌓인 뒤 열 수·코드 메타를 바꾸게 되어 마이그레이션 비용이 붙는다.

### 대상 사용자

사내 위키에 문서를 쌓는 팀원(작성자·열람자). 관리자 전용 기능은 범위 밖.

### 성공지표 (목업 단계 — 검증 가능한 완료 기준)

| # | 기준 |
|---|---|
| S1 | 슬래시 메뉴에서 1~5열을 고를 수 있고, **다섯 경우 모두** 저장 후 복원이 무손실이다 |
| S2 | 기존 2·3열 문서의 직렬화 결과가 **바이트 단위로 이전과 동일**하다(회귀 없음) |
| S3 | 열이 최소 폭 아래로 좁아지면 세로로 쌓여 가로 스크롤이 생기지 않는다 — 760px 본문에서 5열일 때 포함 |
| S4 | 코드 블록에 줄 번호가 보이고, **편집·보기 양쪽에서** 복사하면 줄 번호가 섞이지 않는다 |
| S5 | 빈 문서에서 퀵바의 요소(표·정보 패널·목차)를 눌러 본문에 삽입할 수 있다 |
| S6 | 패널의 저장 마커 ↔ 화면 명칭·색·아이콘 매핑이 표로 확정되고 캡처와 어긋난 항목이 0건이다 |

## 2. 범위

### 포함

- 열 레이아웃 1·4·5열 추가(기존 2·3열 유지), 슬래시 메뉴 항목명·설명·아이콘을 캡처에 맞춤
- 기존 열 블록의 **열 수 변경**
- 코드 블록 줄 번호 — **편집·보기 두 경로 모두**
- 코드 블록 줄바꿈 토글
- 패널 매핑 확정(저장 마커 ↔ 명칭·색·아이콘) 및 아이콘 렌더
- 편집 화면 하단 **요소 퀵바**(표·정보 패널·목차·더 많은 요소)
- 코드 블록 툴바를 하단 플로팅으로 이동

### 명시적 제외

- **템플릿 본체**(회의록·프로젝트 계획 등 실제 양식) — 로드맵 17번 독립 기능. 퀵바의 템플릿 버튼
  자리는 만들지 않는다(눌러도 아무 일이 없는 버튼이 더 나쁘다)
- 열 너비 드래그 조절 — 캡처는 균등 분할만 보여준다
- 검색형 언어 목록 — DS Combobox 신설이 선행 (§4 Could)
- 코드 블록 `</>`(Format code)와 `⋯`(오버플로 메뉴) — §6 P3
- 편집 셸 상단 바(저장됨·공유·링크·⋯) — 07-26 기획에서 이미 다뤘다

## 3. 유저스토리

persona = **작성자**(문서를 쓰는 팀원), **열람자**(읽는 팀원)

### 활동 A — 본문을 여러 열로 배치한다

**A1. 열 수를 1~5에서 고른다** *(Must)*

```
Given 편집 중 슬래시 메뉴를 열었을 때
When "열 3개 레이아웃"을 고르면
Then 본문에 균등한 빈 열 3개가 생기고 첫 열에 커서가 놓인다
```

```
Given 1·2·3·4·5열 각각으로 만든 문서를 저장하고 다시 열었을 때
Then 열 개수와 각 열의 내용이 그대로 복원된다
And 기존 2·3열 문서의 직렬화 결과는 이전과 동일하다
```

**A2. 좁아지면 세로로 쌓인다** *(Must)*

> 열람자로서, 열이 읽을 수 없이 좁아지면 세로로 쌓이기를 원한다.

```
Given 5열이 있는 문서를 기본 본문 폭(760px)에서 열었을 때
Then 각 열이 최소 폭 이상을 확보하거나, 확보할 수 없으면 세로로 쌓인다
And 어느 경우에도 가로 스크롤이 생기지 않는다
```

> [!note] 기준을 뷰포트에서 컨테이너로 바꾼다
> 현재 스택 규칙은 **뷰포트** `max-width: 700px`인데 본문 폭은 `760px`로 고정이다. 화면이 아무리
> 넓어도 5열은 열당 약 130px가 되어 규칙이 발동하지 않는다. **열의 최소 폭**(컨테이너 기준)으로
> 기준을 바꾼다 — 예: `grid-template-columns: repeat(auto-fit, minmax(<최소폭>, 1fr))`.
> 최소 폭 값은 디자이너가 정한다.

**A3. 만든 뒤 열 수를 바꾼다** *(Should)*

> 작성자로서, 3열로 만든 뒤 2열로 줄이고 싶다 — 내용을 잃지 않고.

```
Given 내용이 있는 3열 블록에서 열 수를 2로 바꾸면
Then 열이 2개가 되고 기존 내용이 보존된다(줄어드는 열의 내용은 마지막 열로 합쳐진다)
```

> A3가 없으면 **1열의 존재 이유가 약하다**(§6 P2). 1열은 그 자체로 쓸모가 있다기보다
> "열 수를 바꿀 수 있는 레이아웃의 시작점"이기 때문이다.

### 활동 B — 코드를 읽을 수 있게 넣는다

**B1. 줄 번호를 본다** *(Must)*

```
Given 코드 블록이 있는 문서를 편집 화면과 보기 화면에서 각각 열었을 때
Then 두 화면 모두 각 줄 왼쪽에 줄 번호가 보인다
```

```
Given 줄 번호가 보이는 코드 블록에서
When 복사 버튼을 누르거나 코드를 드래그해 복사하면
Then 줄 번호는 복사되지 않고 원문만 복사된다
```

> [!warning] "표시 전용"이지만 구현 영향은 표시 전용이 아니다
> 편집(`CodeBlockView`)과 보기(`MarkdownView`의 `CodeCopyBlock`)가 **별도 경로**다. 한쪽만
> 고치면 B1의 "문서를 열었을 때"가 충족되지 않는다. 보기 복사는 `pre.textContent`를 읽으므로
> 번호 DOM을 `<pre>` 안에 넣으면 **번호까지 복사된다** — 번호는 `<pre>` 밖 거터에 두고
> `aria-hidden` 처리한다(스크린리더가 숫자를 코드로 읽지 않게).

**B2. 긴 줄을 접어 본다** *(Should)*

```
Given 화면보다 긴 줄이 있는 코드 블록에서
When 줄바꿈 토글을 켜면
Then 긴 줄이 다음 줄로 접히고 가로 스크롤이 사라진다
```

**B3. 언어를 검색해 고른다** *(Could)*

```
Given 코드 블록의 언어 선택을 열고 검색어를 입력하면
Then 일치하는 언어만 목록에 남고
And 고른 언어가 저장 후 다시 열어도 유지된다
```

### 활동 C — 빈 문서에서 첫 요소를 넣는다

**C1. 퀵바로 요소를 삽입한다** *(Should)*

```
Given 빈 문서의 편집 화면 본문 아래 요소 퀵바에서
When "표"를 누르면
Then 본문 커서 위치에 표가 삽입되고 퀵바가 사라진다
```

### 활동 D — 안내 패널을 캡처대로 쓴다

**D1. 패널 매핑을 확정하고 아이콘을 렌더한다** *(Should)*

```
Given 패널 각 종류를 삽입한 문서를 보기 화면에서 열었을 때
Then 매핑표에 정의된 배경색과 아이콘이 각각 렌더된다
```

> 단순 색 대조가 아니다. 파서는 5종(NOTE·TIP·IMPORTANT·WARNING·CAUTION)인데 메뉴는 4종만
> 노출하고, **보기 렌더에 아이콘이 아예 없다**. 캡처의 정보·경고·노트·성공과 현재 명칭이
> 어긋나므로 **저장 마커 ↔ 화면 명칭·색·아이콘 매핑표를 먼저 확정**해야 한다(§6 P7).

## 4. 우선순위 (MoSCoW)

실사용 데이터가 없는 목업 단계라 RICE는 쓰지 않는다(가짜 정밀도만 생긴다).

| 스토리 | 등급 | 임팩트 | 노력 | 근거 |
|---|---|---|---|---|
| A1 열 1~5 | **Must** | 상 | 하 | 저장 문법·엔진이 이미 수용한다. 슬래시 항목 추가 + `Math.max(2,…)` 완화 |
| A2 최소 폭 기반 스택 | **Must** | 상 | 중 | 뷰포트→컨테이너 기준 전환이 필요. 안 하면 A1이 4·5열에서 깨진다 |
| B1 줄 번호(편집+보기) | **Must** | 상 | **중상** | 두 경로 + 복사 분리. 초판이 "하"로 본 것은 보기 경로를 빠뜨린 오판 |
| A3 열 수 변경 | **Should** | 중 | 중 | 1열의 의미를 살리는 스토리(§6 P2) |
| B2 줄바꿈 토글 | **Should** | 중 | 중 | P1 확정으로 저장 포맷 무영향 |
| C1 요소 퀵바 | **Should** | 중 | 중 | 슬래시 커맨드 재사용 가능 |
| D1 패널 매핑·아이콘 | **Should** | 중 | 중 | Could였으나 승격 — 색 대조가 아니라 매핑 확정 + 아이콘 신설 작업이다 |
| P4 툴바 하단 플로팅 | **Should** | 중 | 중 | Won't였으나 승격 — 캡처 충실 복제가 이 리포 1순위 원칙이고, 현 상단 배치는 첫 줄을 가릴 수 있다 |
| B3 언어 검색 | **Could** | 중 | **상** | DS에 검색형 Select가 없어 Combobox 신설 선행. 게다가 편집·보기 **두 레지스트리를 함께** 바꿔야 강조가 어긋나지 않는다 |
| 템플릿 본체 | **Won't** | — | — | 로드맵 17번 독립 기능 |
| 열 너비 드래그 | **Won't** | — | — | 캡처가 균등 분할만 보여준다 |
| `</>` · `⋯` | **Won't** | — | — | §6 P3 |

**MVP = A1 + A2 + B1.**
→ 두 흐름이 각각 완주된다: "열을 원하는 수로 나눠 배치하고 좁아지면 쌓인다"(A1·A2)와
"코드에 줄 번호가 보이고 복사가 깨끗하다"(B1). 셋 다 새 저장 포맷을 만들지 않는다.

## 6. 결정된 정책 (Codex 교차검증 2026-08-03)

| # | 결정 | 근거 | 확신도 |
|---|---|---|---|
| **P1** | 코드 줄 번호·줄바꿈은 **문서에 저장하지 않고 뷰어 전역 프리퍼런스**로 둔다. 기본값은 줄 번호 켬 | 코드펜스 meta에 실으면 GitHub 등 표준 렌더러 호환이 깨진다(패널 `\[!NOTE\]` 이스케이프와 같은 부류). `Page.body` 표준 마크다운·버전 diff 보존이 우선. 컨플루언스는 페이지에 저장하지만 이 리포의 저장 제약이 더 강하다. 저장은 `lib/*` 프리퍼런스 모듈이 담당(store 계약 확장 금지 — 도메인 데이터가 아니다) | 높음 |
| **P2** | 1열은 단순 컨테이너가 아니라 **`columnBlock`의 자식 수 1인 레이아웃**으로 정의한다 → A3(열 수 변경)가 짝을 이룬다 | 컨플루언스도 내용을 보존한 채 열 수를 바꾸는 모델이다. 1열만 있고 변경이 없으면 쓸모가 없다 | 보통 |
| **P3** | `</>`는 **Format code**(JSON·JS·JSX·SQL 한정 포매팅), `⋯`는 오버플로 메뉴. **둘 다 이번 범위 밖** | Format code는 실제 기능이나 대상 언어가 좁다. `⋯`의 구성은 공식 문서에 고정돼 있지 않아 추정 구현은 드리프트다 | `</>` 높음 / `⋯` 보통 |
| **P4** | 코드 블록 툴바를 **하단 플로팅으로 옮긴다**. Won't → **Should** | 캡처와 현행 컨플루언스가 모두 플로팅이고, 이 리포의 1순위 원칙이 "레퍼런스 충실 복제"다. 현 상단 절대 배치는 코드 첫 줄을 가릴 수 있다 | 높음 |
| **P5** | 요소 퀵바는 **빈 문서에서만** 보인다 | 첫 행동 유도 장치다. 내용이 생기면 슬래시·삽입 메뉴가 같은 역할을 하므로 상시 노출은 중복이고 문서 끝을 밀어낸다 | 높음 |
| **P6** | 언어 목록은 **lowlight `common` 37종**으로 제한하고, **선택 목록 = 하이라이터 등록 집합**을 불변조건으로 둔다 | 전체 192종은 초기 번들을 키우고, 편집·보기 두 레지스트리를 함께 바꾸지 않으면 "고를 수는 있는데 강조가 안 되는" 상태가 된다. 현재 고정 15개 목록도 이 집합과 어긋나 있어 함께 정정 | 높음 |
| **P7** | 패널 **매핑표를 디자이너가 확정**한 뒤 구현한다(저장 마커 ↔ 화면 명칭·색·아이콘). 마커 5종 전부를 메뉴에 노출할지도 이때 정한다 | 파서 5종 / 메뉴 4종 / 아이콘 0개로 세 층이 어긋나 있다. 매핑 없이 색만 맞추면 의미가 뒤섞인다 | 높음 |

**남은 ⚠️ 확인필요**: 없음. P2는 확신도 보통이라 구현 중 레퍼런스와 어긋나면 되돌린다.

## 7. 테스트 · 마이그레이션 전략

기존 문서 마이그레이션은 **불필요**하다(문법 무변경). 대신 회귀를 테스트로 고정한다.

| 대상 | 검증 |
|---|---|
| 열 직렬화 | 1·2·3·4·5열 각각의 편집→마크다운→편집 왕복 fixture. **기존 2·3열 출력이 바이트 동일**한지 대조(회귀 가드) |
| 열 수 변경 | 3→2 축소 시 내용 보존, 2→4 확장 시 빈 열 추가 |
| 보기 렌더 | 1·4·5열이 `remarkColumns`로 같은 구조가 되는지 |
| 코드 복사 | 편집·보기 **양쪽**에서 줄 번호가 복사물에 섞이지 않는지. 빈 마지막 줄·긴 줄 포함 |
| 접근성 | 줄 번호 거터가 `aria-hidden`인지, 퀵바·툴바가 키보드로 도달 가능한지 |
| 반응형 | 760px 본문에서 5열이 스택되는지 — jsdom으로는 레이아웃이 안 잡히므로 **실브라우저 확인 필요** |
| 번들 | fresh build의 gzip 크기와 chunk 구성을 착수 전/후로 대조. **초판이 인용한 "515kB"는 과거 원장의 비압축 추정치라 근거로 쓰지 않는다** |
