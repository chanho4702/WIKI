## 0. 착수 전 실측한 현재 상태

기획 전에 코드로 확인했다. **이미 있는 것을 다시 기획하지 않기 위해서다** — 아래는 추정이 아니라 실측이다.

| 영역 | 현재 구현 | 근거 |
|---|---|---|
| 열 레이아웃 | `setColumns(count)`가 임의 개수 지원. **슬래시 메뉴엔 2·3열만** 노출. `Math.max(2, count)`가 1열을 막는다 | `editor/extensions/columns.ts`, `extensions/slashMenu.ts` |
| 저장 포맷(열) | `::::columns` / `:::column` 확장 문법으로 **이미 확정·구현**. 편집(markdown-it 컨테이너)·보기(remark-directive) 양쪽 왕복 동작 | `columns.ts`, `lib/remarkColumns.ts` |
| 코드 블록 | 구문 강조(lowlight, 자동감지 끔) + **언어 선택 select(고정 15개)** + **복사 버튼** 이미 있음 | `editor/components/CodeBlockView.tsx` |
| 코드 블록 | 줄 번호 없음 · 줄바꿈 토글 없음 · 언어 목록 검색 불가 · 툴바는 블록 상단 고정(캡처는 하단 플로팅) | 같은 파일 |
| 패널 | 노트/팁/경고/주의 4종 존재(GitHub Alerts `> [!NOTE]` 기반) | `lib/remarkAlerts.ts`, `extensions/slashMenu.ts` |
| 템플릿 퀵바 | **없음** | 로드맵 17번 "템플릿"이 미착수 상태 |

> [!important] 앞선 오판 정정
> 착수 직전 구두 갭 분석에서 "코드 블록에 언어 선택 UI가 없다"고 했으나 **틀렸다**. 언어 선택과
> 복사 버튼은 이미 있다. 실제 갭은 줄 번호·줄바꿈 토글·검색형 언어 목록·툴바 위치다.

## 1. 문제 정의

### 문제

문서를 "읽을 수 있게" 만드는 편집 요소가 절반만 있다. 세 갈래로 갈린다.

1. **열 레이아웃이 2·3열에 갇혀 있다.** 레퍼런스는 1~5열을 준다. 특히 **1열 레이아웃**은
   "전체 폭 문단 안에 블록을 담는" 용도라 다른 열 수와 성격이 다른데, 코드가 `Math.max(2, …)`로
   아예 막고 있다. 07-26 기획이 "3열 초과·열 너비 조절"을 제외로 잘랐는데, 그 근거는 당시
   레퍼런스에 없었기 때문이었다 — 이번 캡처가 그 전제를 뒤집는다.
2. **코드 블록이 길어지면 읽히지 않는다.** 줄 번호가 없어 리뷰에서 "몇 번째 줄"을 가리킬 수 없고,
   긴 줄은 가로로 흘러 잘린다(줄바꿈 토글 없음). 언어 목록은 15개 고정이라 목록에 없는 언어를
   쓰는 문서는 강조를 포기해야 한다.
3. **빈 문서 앞에서 무엇을 해야 할지 모른다.** 레퍼런스는 본문 아래에 템플릿·요소 퀵바를 깔아
   첫 행동을 유도하는데, 우리는 플레이스홀더 한 줄뿐이다.

### 왜 지금인가

편집기 코어(블록·마크다운 왕복·열·패널·코드 강조)가 완성돼 있어, 이번 작업은 **새 저장 포맷을
거의 만들지 않고 기존 것을 넓히는 일**이다. 반대로 지금 미루면 문서가 쌓인 뒤에 열 수·코드
메타를 바꾸게 되어 마이그레이션 비용이 붙는다.

### 대상 사용자

사내 위키에 문서를 쌓는 팀원(작성자·열람자). 관리자 전용 기능은 범위 밖.

### 성공지표 (목업 단계 — 검증 가능한 완료 기준)

| # | 기준 |
|---|---|
| S1 | 슬래시 메뉴에서 1~5열을 고를 수 있고, 저장 후 다시 열었을 때 열 구성이 그대로 복원된다(마크다운 왕복 무손실) |
| S2 | 좁은 화면에서 4·5열이 세로로 쌓여 가로 스크롤이 생기지 않는다 |
| S3 | 코드 블록에 줄 번호가 보이고, 줄바꿈을 켜면 긴 줄이 잘리지 않는다 |
| S4 | 언어 목록을 검색해 고를 수 있고, 고른 언어가 저장·복원된다 |
| S5 | 빈 문서에서 퀵바의 요소(표·정보 패널·목차)를 눌러 본문에 삽입할 수 있다 |
| S6 | 패널 4종의 색·아이콘이 캡처와 대조되어 어긋난 항목이 0건이다 |

## 2. 범위

### 포함

- 열 레이아웃 1·4·5열 추가 (기존 2·3열 유지), 슬래시 메뉴 항목명·설명·아이콘을 캡처에 맞춤
- 코드 블록: 줄 번호, 줄바꿈 토글, 검색 가능한 언어 목록
- 패널 4종 색·아이콘 캡처 대조 및 정정
- 편집 화면 하단 **요소 퀵바**(표·정보 패널·목차·더 많은 요소)

### 명시적 제외

- **템플릿 본체**(회의록·프로젝트 계획 등 실제 양식 문서) — 로드맵 17번의 독립 기능이다.
  이번엔 퀵바의 **요소 삽입 4종만** 하고, 템플릿 버튼 자리는 만들지 않는다(빈 버튼을 두면
  눌러보고 아무 일도 안 일어나는 게 더 나쁘다)
- 열 너비 드래그 조절 — 캡처는 "동일한 열"만 보여준다(균등 분할)
- 코드 블록 `⋯` 더보기 메뉴, `</>` 버튼의 정확한 동작 — 캡처만으로는 무엇인지 확정 불가 (§6 P3)
- 코드 블록 툴바를 하단 플로팅으로 옮기는 것 — 시각 배치 변경이라 디자이너 판단 선행 (§6 P4)
- 편집 셸 상단 바(저장됨·공유·링크·⋯)는 07-26 기획에서 이미 다뤘다 — 중복 기획하지 않는다

## 3. 유저스토리

persona = **작성자**(문서를 쓰는 팀원), **열람자**(읽는 팀원)

### 활동 A — 본문을 여러 열로 배치한다

**A1. 열 수를 1~5에서 고른다** *(Must)*

> 작성자로서, 내용 성격에 맞는 열 수를 골라 배치하고 싶다.

```
Given 편집 중 슬래시 메뉴를 열었을 때
When "열 3개 레이아웃"을 고르면
Then 본문에 균등한 빈 열 3개가 생기고 첫 열에 커서가 놓인다
```

```
Given 1~5열 중 어느 것으로든 만든 문서를 저장하고 다시 열었을 때
Then 열 개수와 각 열의 내용이 그대로 복원된다
```

**A2. 좁은 화면에서 읽을 수 있다** *(Must)*

> 열람자로서, 좁은 화면에서도 가로 스크롤 없이 읽고 싶다.

```
Given 4열 또는 5열이 있는 문서를 좁은 화면에서 열었을 때
Then 열이 세로로 쌓이고 가로 스크롤이 생기지 않는다
```

### 활동 B — 코드를 읽을 수 있게 넣는다

**B1. 줄 번호를 본다** *(Must)*

> 열람자로서, 코드 리뷰 중 "몇 번째 줄"을 가리키고 싶다.

```
Given 코드 블록이 있는 문서를 열었을 때
Then 각 줄 왼쪽에 줄 번호가 보이고
And 코드를 복사하면 줄 번호는 복사되지 않는다
```

**B2. 긴 줄을 접어 본다** *(Should)*

> 열람자로서, 가로로 흘러 잘리는 긴 줄을 접어서 보고 싶다.

```
Given 화면보다 긴 줄이 있는 코드 블록에서
When 줄바꿈 토글을 켜면
Then 긴 줄이 다음 줄로 접히고 가로 스크롤이 사라진다
```

**B3. 언어를 검색해 고른다** *(Should)*

> 작성자로서, 목록에 안 보이는 언어도 찾아서 지정하고 싶다.

```
Given 코드 블록의 언어 선택을 열고 검색어를 입력하면
Then 일치하는 언어만 목록에 남고
And 고른 언어가 저장 후 다시 열어도 유지된다
```

### 활동 C — 빈 문서에서 첫 요소를 넣는다

**C1. 퀵바로 요소를 삽입한다** *(Should)*

> 작성자로서, 슬래시 문법을 몰라도 자주 쓰는 요소를 눌러 넣고 싶다.

```
Given 편집 화면 본문 아래 요소 퀵바에서
When "표"를 누르면
Then 본문 커서 위치에 표가 삽입된다
```

### 활동 D — 안내 패널을 캡처대로 쓴다

**D1. 패널 색·아이콘이 레퍼런스와 같다** *(Could)*

> 열람자로서, 패널 색만 보고 정보/경고/노트/성공을 구분하고 싶다.

```
Given 패널 4종을 각각 삽입한 문서를 보기 화면에서 열었을 때
Then 각 패널의 배경색과 아이콘이 캡처(`기능들.png`)와 일치한다
```

## 4. 우선순위 (MoSCoW)

실사용 데이터가 없는 목업 단계라 RICE는 쓰지 않는다(가짜 정밀도만 생긴다). 정성적 임팩트/노력으로 줄 세운다.

| 스토리 | 등급 | 임팩트 | 노력 | 근거 |
|---|---|---|---|---|
| A1 열 1~5 | **Must** | 상 | **하** | 저장 포맷·엔진 모두 이미 있다. 슬래시 항목 추가 + `Math.max(2,…)` 완화가 거의 전부 |
| A2 반응형 스택 | **Must** | 상 | 하 | 2·3열 CSS가 이미 있으므로 4·5열로 넓히는 수준. 안 하면 A1이 좁은 화면을 깨뜨린다 |
| B1 줄 번호 | **Must** | 상 | 중 | 코드 블록의 가장 큰 결핍. 표시 전용이라 저장 포맷 무영향 |
| B2 줄바꿈 토글 | **Should** | 중 | 중 | 저장 여부가 열린 결정(§6 P1)에 걸린다 |
| B3 언어 검색 | **Could** | 중 | **상** | 이미 select가 있어 "개선"이지 "부재"다. **DS에 검색형 Select가 없다**(실측 §5) → DS Combobox 신설 + 버전 bump·tarball·overrides 갱신이 따라온다. 임팩트 대비 비용이 커 Should에서 내렸다 |
| C1 요소 퀵바 | **Should** | 중 | 중 | 빈 문서 이탈을 줄인다. 슬래시 메뉴 커맨드 재사용 가능 |
| D1 패널 대조 | **Could** | 하 | **하** | 이미 4종이 동작한다 — 색·아이콘 대조뿐 |
| 템플릿 본체 | **Won't** | — | — | 로드맵 17번 독립 기능 (§2 제외) |
| 열 너비 드래그 | **Won't** | — | — | 캡처가 균등 분할만 보여준다 |
| 툴바 하단 플로팅 이동 | **Won't** | — | — | 디자이너 판단 선행 (§6 P4) |

**MVP 수평 슬라이스 = A1 + A2 + B1.**
→ "열을 원하는 수로 나눠 배치하고, 좁은 화면에서도 읽히고, 코드에 줄 번호가 보인다"가 얇게 한 번 완주된다.
셋 다 기존 구조를 넓히는 작업이라 새 저장 포맷을 만들지 않는다.

## 5. 영향 리포 / 크로스커팅

| 대상 | 영향 |
|---|---|
| `wiki-front` | 전부 여기 — 에디터 확장(`columns.ts`·`slashMenu.ts`·`CodeBlockView.tsx`), 보기 렌더(`remarkColumns.ts`), `app.css` |
| `design-system` (`@chanho`) | **실측: 검색형 Select가 없다.** `Select`는 Radix Select 래퍼로 필터 입력이 없다(`packages/react/src/Select/Select.tsx`). B3를 하려면 DS에 **Combobox를 신설**한 뒤 소비해야 한다(CLAUDE.md 불변조건 4 — 타 UI 라이브러리 금지). 따라오는 비용: DS 수정 → `typecheck`/`test`/`lint:css` → `build` → 버전 bump → `pnpm pack` → 소비 리포의 `package.json` **및** `pnpm-workspace.yaml` overrides **양쪽** 갱신 → `pnpm install`. B3를 Could로 내린 이유 |
| `wiki-backend` | **영향 없음.** `Page.body`는 계속 마크다운 문자열이고 열·코드는 본문 안에서 해결된다. API 계약·버전 diff·`[[링크]]` 파이프라인 무변경 |
| 게이트웨이 / 인증 / org-service | 영향 없음 |

**저장 포맷 (CLAUDE.md 불변조건 2)**

- 열 1~5: `::::columns` / `:::column` 확장 문법을 **그대로 재사용**한다 — 열 개수는 자식 `:::column` 수로 표현되므로 문법 변경이 없다. ✅ 재논의 불필요
- 코드 줄 번호: **표시 전용**으로 두면 저장 포맷 무영향 ✅
- 코드 줄바꿈: 문서별로 기억하려면 코드펜스 meta(``` ```ts wrap ```)에 실어야 한다 → **⚠️ 저장 포맷 재논의** (§6 P1)

## 6. 열린 정책 결정

| # | 결정할 것 | 상태 |
