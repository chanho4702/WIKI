# 컨플루언스 설치형(Server/DC) 마이그레이션 모듈 — 기획 (2026-09-05)

사용자 지시(2026-09-05): "나중에 컨플 설치형 마이그레이션이 가능해야 한다. 마이그레이션 모듈을 만드는 것이 목표."
이 문서는 **무엇을·왜·얼마나 중요한지**까지다. 아키텍처·API·핸들러 설계는 다음 단계
(`docs/superpowers/specs/`)에서 정한다. 기존 결정과 충돌하지 않도록 아래 문서를 전제로 한다:
`docs/backend/2026-08-16-w14-content-collaboration-architecture.md`(ADR-W14-04 IR 계약, ADR-W14-07 import-only·재실행 가능 잡, §5 IR 호환 규칙, §6 게이트 G1~G5),
`docs/roadmap/2026-08-16-notion-confluence-gap-analysis.md` §4.7·§6·§7.

## 1. 문제 정의

**문제.** 설치형 컨플루언스(Server는 2024-02 지원 종료, DC는 라이선스 갱신 부담)에서 빠져나오려는 팀이
우리 위키로 옮길 길이 없다. 위키 자체는 컨플루언스 파리티가 끝났지만(`2026-08-28-confluence-feature-parity.md`),
**데이터가 못 넘어오면 파리티는 쓸모가 없다**. 온프렘 단일테넌트 제품이라는 포지셔닝(`deployment-model` 결정)에서
"기존 컨플 DC를 대체한다"가 가장 현실적인 도입 시나리오이기도 하다.

**지금 상태(2026-09-05 실측).** wiki-backend `migration/` 패키지는 잡·체크포인트(V6/V7)·워커 리스·재시도·
데드레터·IR v1 JSON 스키마와 검증기·컨플 storage XHTML 정규화기(패널 5종·코드·미지원 매크로 `opaque+sourceRef`)·
손실 보고서 API까지 갖춘 **골격**이다. 그러나 **단계 핸들러(EXTRACT→NORMALIZE→MEDIA_COPY→RESOLVE→VERIFY)가 하나도
없고, IR을 Page로 쓰는 코드도 없으며, 정규화기는 아무도 주입하지 않는다.** 즉 잡을 만들면 모든 항목이
`STAGE_HANDLER_UNAVAILABLE`로 데드레터된다. 프론트에는 관리 화면·스토어가 전혀 없다. 별개로 myFront의
docs 임포터(`sync-docs.mjs`)는 마이그레이션 엔진을 쓰지 않고 페이지 CRUD + 클라이언트 매핑 파일로 동작한다
(공개 docs 인스턴스는 `/api/wiki/migrations/**`를 차단).

**대상 사용자.**
- **이관 담당 관리자**(위키 전역/스페이스 ADMIN): 원본 DC 사이트 정보를 넣고, dry-run 결과를 보고, 실행·재개·중단하고,
  손실 보고서를 읽고 팀에 알린다.
- **온프렘 운영자**: 원본 DC와 위키 사이의 네트워크·인증(PAT)·저장소 용량을 준비한다.
- **일반 사용자**: 이관 뒤 예전 링크·첨부·작성자·수정일이 그대로 보이길 기대한다.

**성공지표(검증 가능한 완료 기준 — 실사용 데이터가 없으므로 시나리오로 대체).**
| # | 기준 | 측정 |
|---|---|---|
| S1 | 샘플 DC 스페이스(페이지 500·첨부 200·깊이 6·라벨·제한 포함) 1개를 **dry-run → 실행 → 재실행**해 완주 | 재실행 시 새 페이지 0건(멱등), 잡 상태 DONE |
| S2 | 페이지·첨부 수가 원본과 100% 대조되고, 대조 실패는 손실 보고서에 항목으로 남는다 | VERIFY 단계 리포트 |
| S3 | 본문 내부 링크(페이지·첨부·앵커)의 90% 이상이 우리 위키 링크로 재작성, 나머지는 보고서에 원본 URL 유지 | RESOLVE 통계 |
| S4 | 미지원 매크로는 본문에서 사라지지 않고 `opaque` 표시로 남으며 보고서에 종류·건수가 집계된다 | 손실 보고서 |
| S5 | 작성자·수정자·시각이 보존되고, 미매핑 사용자는 정해진 기본값으로 표시된다 | 페이지 메타 대조 |
| S6 | 관리자가 UI에서 진행률·실패 항목·보고서를 보고 재개할 수 있다 | 관리 화면 E2E |

## 2. 범위

**포함(이 모듈).**
- 원본: **Confluence Server/Data Center**, REST API(`/rest/api/content`, ancestors·attachments·history·labels·restrictions)로 **온라인 추출**.
  인증은 개인 액세스 토큰(PAT, DC 7.9+) 우선.
- 단위: **스페이스 1개 = 잡 1개**. 대상 스페이스는 새로 만들거나 기존 빈 스페이스에 넣는다.
- 옮기는 것: 페이지 트리(부모·순서), 본문(storage XHTML → IR → 마크다운), 첨부(파일 본체·버전은 최신본), 라벨, 페이지 제한(보기/편집),
  작성자·수정자·생성/수정 시각, 블로그 글(`type=blog`), 페이지 댓글(최상위 + 답글).
- 운영: dry-run(쓰기 없이 추출·정규화·보고서), 재개·재실행 멱등, 손실 보고서, 관리 화면.

**명시적 제외.**
- 클라우드 컨플루언스 라이브 커넥터(보류 유지 — 별도 결정), Notion 라이브 추출기(같은 파이프라인이지만 이 문서 범위 밖).
- 화이트보드·데이터베이스·Jira 매크로 실체·애드온(Draw.io, Gliffy 등) 데이터 — `opaque` 보존까지만.
- 사용자 계정 생성·Keycloak 프로비저닝 — 사용자는 **이메일로 대조**만 한다(계정 만들기는 인증 플랫폼 몫).
- 스페이스 권한(그룹·역할)의 자동 부여 — 보고서에 "원본 권한 요약"만 남기고 관리자가 org-service에서 설정(❓ §6).
- 첨부 **버전 이력** 전체, 페이지 **버전 이력** 전체(최신 N개만 — ❓ §6).
- XML 사이트 백업 파일 임포트(오프라인) — Could, 후속.

## 3. 유저스토리 매핑

| Persona | Activity | Story | AC |
|---|---|---|---|
| 이관 관리자 | 연결 | **M-01** 원본 DC URL·PAT·스페이스 키를 넣고 접속을 확인한다 | Given 유효한 PAT / When 확인 / Then 원본 스페이스 이름·페이지 수·첨부 용량이 보인다. 권한 없는 PAT면 원인 문구 |
| 이관 관리자 | 미리 보기 | **M-02** dry-run으로 무엇이 넘어오고 무엇이 손실되는지 본다 | Given 연결됨 / When dry-run / Then 쓰기 0건, 보고서에 페이지·첨부 수·미지원 매크로 종류·미매핑 사용자 목록 |
| 이관 관리자 | 실행 | **M-03** 실행하면 페이지 트리·본문·첨부·라벨·제한·메타가 대상 스페이스에 생긴다 | Given dry-run 통과 / When 실행 / Then S1·S2·S5 충족, 진행률이 화면에 갱신된다 |
| 이관 관리자 | 복구 | **M-04** 중간에 끊겨도 재개하면 이어서 하고, 다시 돌려도 중복이 안 생긴다 | Given 실행 중 중단 / When 재개 / Then 완료 항목은 건너뛰고 미완료만 처리(S1 멱등) |
| 이관 관리자 | 검토 | **M-05** 손실 보고서를 심각도·종류별로 읽고 항목에서 원본 페이지로 이동한다 | Given DONE / When 보고서 열기 / Then 심각도순 목록, 각 항목에 원본 URL·대상 페이지 링크 |
| 일반 사용자 | 열람 | **M-06** 옮겨진 문서의 내부 링크·첨부·이미지가 그대로 열린다 | Given 이관 완료 / When 문서 열기 / Then 링크가 위키 문서로 가고(S3), 이미지가 보이며, 못 옮긴 매크로 자리에 원본 표시 |
| 일반 사용자 | 열람 | **M-07** 작성자·수정일이 원본과 같다 | Given 이관 완료 / Then 메타 줄의 작성자·시각이 원본과 일치, 미매핑 사용자는 이름 텍스트로 표시 |
| 운영자 | 준비 | **M-08** 이관에 필요한 네트워크·토큰·용량 조건을 문서로 안다 | Given 설치 가이드 / Then PAT 발급 절차·아웃바운드 허용·예상 저장 용량 계산법이 있다 |

MVP(수평 슬라이스) = M-01 → M-02 → M-03(페이지 트리·본문·메타만) → M-04 → M-05. 첨부·링크 재작성·제한·댓글·블로그는 그 위에 얹는다.

## 4. 우선순위 (MoSCoW — 실사용 데이터가 없어 RICE는 쓰지 않는다)

| 등급 | 항목 | 이유 |
|---|---|---|
| **Must** | DC REST 추출기(EXTRACT), XHTML→IR(NORMALIZE, 정규화기 주입), IR→Page 작성기, VERIFY 대조, 재개·멱등, dry-run, 손실 보고서 UI, 진행률 화면 | 없으면 "이관"이라 부를 수 없는 최소 흐름 |
| **Must** | 페이지 트리·순서, 작성자·수정자·시각 보존, 미매핑 사용자 기본값 | S1·S5 |
| **Should** | 첨부 본체 복사(MEDIA_COPY) + 본문 참조 재작성, 내부 링크·앵커 재작성(RESOLVE), 라벨, 페이지 제한 → V12 제한 | S2·S3·M-06 |
| **Should** | 블로그 글, 페이지 댓글 | 파리티 기능이 이미 있어 받을 곳이 있다 |
| **Could** | 페이지 버전 이력 최신 N개, XML 백업 파일 임포트, 스페이스 권한 자동 부여 | 정책 결정 선행 |
| **Won't(이번)** | 클라우드 라이브 커넥터, Notion 라이브 추출기, 애드온 데이터 실체화, 사용자 계정 생성 | §2 제외 |

**단계 제안(구현 계획의 입력, 확정 아님):** M1 파이프라인 완주(핸들러 5개·작성기·최소 관리 화면) → M2 첨부·링크·라벨·제한 →
M3 블로그·댓글·버전 N개 → M4 XML 백업·검증 리포트 고도화·설치 가이드.

## 5. 영향 리포 / 크로스커팅

| 리포 | 영향 |
|---|---|
| **wiki-backend** (주) | `migration/` 핸들러·IR→Page 작성기·DC 클라이언트·아웃바운드 HTTP(타임아웃·재시도·rate limit)·저장소 용량. 첨부는 MinIO/S3 어댑터 재사용 |
| **wiki-front** | 관리 화면(전역 관리자): 연결·dry-run·실행·진행률·보고서. 스토어 `wikiStore` 경유, 듀얼모드(목업은 고정 시나리오) |
| **platform-backend(org-service)** | 사용자 이메일 대조 조회, 페이지 제한 부여 API 재사용. 스페이스 권한 자동 부여는 이번 범위 밖 |
| **auth/Keycloak** | 변경 없음 — 미등록 사용자는 만들지 않는다 |
| **gateway/nginx** | 변경 없음 — 원본 DC 접근은 백엔드 아웃바운드. 온프렘 방화벽 아웃바운드 허용은 설치 가이드 항목 |
| **infra-settings** | 워커 활성 플래그(`platform.wiki.migration-worker.enabled`)·아웃바운드 프록시·PAT 시크릿 보관 |

## 6. 열린 정책 결정 (이 리포 컨벤션: ❓ 정책대기 / ⚠️ 확인필요)

| # | 결정 | 기본 제안 |
|---|---|---|
| ❓ P1 | 지원 DC 버전 범위 | 7.19 LTS ~ 9.x. 7.9 미만(PAT 없음)은 basic auth 옵션으로만 |
| ❓ P2 | 미매핑 사용자 기본값 | 시스템 사용자 "이관됨(원본 이름)"으로 표시하되 원본 사용자명을 메타에 보존, 나중에 계정이 생기면 재대조 |
| ❓ P3 | 페이지 버전 이력 | 최신 1개(현재본)만 Must, N개(기본 10)는 Could |
| ❓ P4 | 미지원 매크로 손실 허용 | 항상 `opaque`로 남기고 실행은 막지 않는다. "손실 0건일 때만 실행" 옵션은 관리자가 켠다 |
| ❓ P5 | 댓글 이관 시 작성자·시각 | 원본 그대로(P2 규칙 적용). 인라인 댓글은 앵커 재현이 어려워 페이지 댓글로 강등 |
| ❓ P6 | 대상 스페이스 키 충돌 | 원본 키 우선, 충돌 시 관리자가 새 키 입력(자동 접미사 금지) |
| ⚠️ P7 | 실행 주체 | 서버 워커(기존 설계) 유지. 로컬 CLI 임포터(docs 방식)는 이 모듈로 흡수하지 않는다 — 두 경로가 따로 있다는 점을 문서화 |
| ⚠️ P8 | 인증 | PAT 우선, 시크릿은 서버 측 보관·화면 재노출 금지 |
| ⚠️ P9 | 페이지 제한 매핑 | 원본 view/edit 제한 → V12 제한. 그룹 제한은 팀(team)으로 대조되지 않으면 보고서에 남기고 부여하지 않는다(fail-open 금지 원칙과 충돌 여부 확인) |
