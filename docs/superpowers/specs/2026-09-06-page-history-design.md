# 페이지 히스토리 화면 — 컨플루언스 충실 복제 (2026-09-06)

사용자: "버전 히스토리 보기 어렵다. UI/UX 개선, 컨플 따라하면 됨."
현재는 `HistoryModal`(모달 안 좌측 목록 + 우측 미리보기/변경사항 탭 + 비교 기준 select). 문제: 모달이라 좁고, 버전이 많아지면 목록이 스크롤에 묻히고, "누가·언제·왜"가 한 줄에 눌려 읽히지 않으며, 두 버전 비교가 select 조합이라 발견되지 않는다.

레퍼런스 = 컨플루언스 클라우드 **페이지 히스토리**(페이지 ⋯ 메뉴 → "페이지 히스토리") 3화면: (1) 히스토리 표, (2) 이전 버전 보기, (3) 두 버전 비교. 아래 구성이 스펙이다 — 항목·순서·문구를 임의로 바꾸지 않는다. 레퍼런스에 있으나 우리 백엔드에 없는 것은 "후속"으로 명시하고 무음 누락하지 않는다.

## 1. 라우트 (모달 → 전용 화면)

기존 페이지 라우트 패턴(`App.tsx`의 `/spaces/:spaceId/...` + `WikiLayout`)을 그대로 따른다.

| 경로 | 화면 |
|---|---|
| `…/pages/:pageId/history` | **PageHistoryPage** — 히스토리 표 |
| `…/pages/:pageId/history/:version` | **PageVersionPage** — 이전 버전 보기(`version`은 버전 번호) |
| `…/pages/:pageId/history/compare?from=3&to=5` | **PageCompareVersionsPage** — 두 버전 비교 |

진입: PageViewPage 우상단 히스토리 아이콘 버튼(aria-label "히스토리", 유지) → 히스토리 표로 이동. ⋯(더보기) 메뉴가 있으면 "페이지 히스토리" 항목도 추가. `HistoryModal`은 삭제하고 테스트(App.w3-history·w4-history-diff·w22-version-history·w2-view의 관련 부분)를 새 화면으로 이관한다 — 기대치를 약화시키지 않는다(직전 비교·임의 기준 비교·복원·no-op·이름 폴백·변경 요약 표시 전부 새 화면에서 검증).

## 2. 화면 (1) 히스토리 표

```
[← 페이지 제목]                                  (뒤로 링크: 페이지 보기)
페이지 히스토리                                   h1
비교할 버전 2개를 선택하세요.      [선택한 버전 비교]   (Button primary, 정확히 2개 선택 때만 활성)

┌─┬────────┬──────────────┬───────────────────┬────────────────┬──────────────┐
│☐│ 버전   │ 변경한 사람   │ 날짜              │ 변경 요약       │ 작업         │
├─┼────────┼──────────────┼───────────────────┼────────────────┼──────────────┤
│☐│ v. 7 현재│ ◯ 김찬호     │ 2026. 9. 6. 오후 2:10│ 표 열 너비 조절 │              │
│☐│ v. 6   │ ◯ 사용자 #12  │ 2026. 9. 5. 오전 9:02│ —              │ 이 버전으로 복원│
│☐│ v. 5   │ ◯ 이관됨 · 홍길동│ …               │ 컨플루언스 재이관 v3│ 이 버전으로 복원│
└─┴────────┴──────────────┴───────────────────┴────────────────┴──────────────┘
```

- 최신순. 표는 DS `Table`(열 너비 조절 가능하면 사용). 각 행:
  - **선택**: DS `Checkbox`(`onCheckedChange`), aria-label "v. N 선택". 3개째를 고르면 가장 먼저 고른 것을 해제(컨플과 같은 2개 제한 — 대안: 3개째 비활성. 둘 중 **2개 제한 해제 방식**을 쓴다).
  - **버전**: 링크 "v. N" → 이전 버전 보기. 현재 버전 행은 `Badge`/`Lozenge` "현재"(DS에 있는 것으로).
  - **변경한 사람**: DS `Avatar size="small"` + 이름. 이름 규칙은 기존 `userName`(디렉터리 → 저장 시점 스냅샷 `savedByName` → `사용자 #{id}` → "알 수 없음") 그대로.
  - **날짜**: `toLocaleString("ko-KR")` 절대시각. 빈 값·무효는 "" (Invalid Date 금지). `title`에 ISO 원문.
  - **변경 요약**: `changeNote` 없으면 "—".
  - **작업**: "이 버전으로 복원"(Button subtle) — 현재 버전 행에는 없음. 컨플의 "삭제"(버전 삭제)는 백엔드 API가 없어 **후속**(화면에 넣지 않는다, 문서에 남긴다).
- 상단 도구줄: 안내 문구 + "선택한 버전 비교" → `history/compare?from=낮은버전&to=높은버전`.
- 상태: 로딩 `SkeletonLines`, 실패는 빈 표가 아니라 에러 상태(문구 + 다시 시도), 버전 0개는 "아직 저장된 버전이 없습니다".
- 키보드: 체크박스·링크·버튼 전부 탭 순회, 포커스 링은 DS 기본.

## 3. 화면 (2) 이전 버전 보기

```
┃ 이전 버전(v. 5)을 보고 있습니다. 홍길동 · 2026. 9. 5. 오전 9:02 · "컨플루언스 재이관 v3"   [현재 버전 보기]
┃                                                           [현재 버전과 비교] [이 버전으로 복원]
제목(그 시점)
본문(MarkdownView, 읽기 전용)
```

- 상단 배너는 DS의 메시지/배너 컴포넌트(있으면 `Banner`/`SectionMessage`/`Callout` 중 실존하는 것, 없으면 `app.css`에 `--chanho-*` 토큰으로 `.history-banner`). appearance는 정보(info).
- 현재 버전이면 배너 대신 "현재 버전입니다" 한 줄 + 히스토리로 돌아가기.
- "현재 버전과 비교" → `history/compare?from=N&to=현재`.
- 본문은 `getVersion`으로 그때 읽는다(목록은 메타만).

## 4. 화면 (3) 두 버전 비교

```
[← 페이지 히스토리]
v. 3 ↔ v. 5 비교                                   h1
┌ v. 3 ────────────────┐   ┌ v. 5 ────────────────┐
│ ◯ 김찬호 · 날짜 · 요약 │   │ ◯ 홍길동 · 날짜 · 요약 │   [v. 5로 복원]
└──────────────────────┘   └──────────────────────┘
제목: 옛 제목 → 새 제목            (제목이 바뀌었을 때만)
DiffView(oldText=v.3 본문, newText=v.5 본문)
```

- `from`<`to`가 아니면 바꿔서 보여준다. 둘 중 하나가 없으면 에러 상태.
- 기존 `DiffView` 재사용(추가·삭제 색은 이미 토큰). 컨플의 "이전 변경/다음 변경" 점프 버튼은 **후속**.
- "v. N로 복원"은 `to`가 현재가 아닐 때만.

## 5. 복원 흐름 (컨플: 확인 다이얼로그 + 버전 코멘트)

- 어느 화면에서든 "이 버전으로 복원" → DS `Modal` "v. N으로 복원할까요?" 본문 "v. N 내용으로 새 버전이 만들어집니다. 현재 내용은 히스토리에 그대로 남습니다." + `TextField` "변경 요약"(기본값 `v. N에서 복원`) + [복원] [취소].
- 스토어 계약 확장: `restoreVersion(pageId, versionId, changeNote?)`. 목업은 새 버전의 `changeNote`에 기록. API 어댑터는 `POST /api/wiki/pages/{id}/revisions/{v}/restore` 본문 `{ changeNote }`로 보낸다 — **백엔드는 아직 본문을 읽지 않는다(후속 X: RevisionController.restore에 선택 본문 추가)**. 계약 문서 `docs/backend/2026-07-17-wiki-service-requirements.md`의 restoreVersion 행에 이 사실을 적는다.
- 결과 토스트는 기존 문구 유지("v{N} 버전으로 복원했습니다" / "현재 내용과 동일합니다 — 변경 없음"). no-op 판정 규칙(목업 `updatedAt` 비교, 백엔드는 항상 새 버전) 그대로. 복원 뒤 페이지 보기로 이동.

## 6. 접근성·스타일

- 색·간격·radius 전부 `var(--chanho-*)`, `app.css`에 `.history-page`·`.history-table`·`.history-banner`·`.history-compare-meta`. 하드코딩 hex 금지, 다크 모드 확인.
- 아이콘 전용 버튼은 aria-label. 표 헤더는 `th`. 상태를 색으로만 구분하지 않는다("현재"는 텍스트 배지).
- 테스트는 role/accessible-name 쿼리. 화면 통합 테스트는 `src/app/App.w30-page-history.test.tsx`(W30) + 기존 히스토리 테스트 이관.

## 7. 후속(레퍼런스에 있으나 이번엔 없음)

- 버전 삭제(백엔드 API 없음)
- 비교 화면의 이전/다음 변경 점프
- 백엔드 restore 변경 요약 수용(X: wiki-backend `RevisionController.restore` 선택 본문)
